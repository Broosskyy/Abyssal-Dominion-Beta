# Android 305903 updater recovery

A device on 305902/data 243 reported the generic "Daten-Download unterbrochen" state while the data-246 release and its 124,533,818-byte asset were reachable. The old controller discarded Android's reason code and had no independent transfer path. The screenshot alone does not establish the device's exact transport error.

305903 / 0.305.9-test.3 embeds the full current game and adds an independent threaded HTTP-to-file recovery transport for both game data and APK updates. Failed native requests, enqueue errors and prolonged paused requests switch to that path. Direct requests have bounded retries, a 45-second no-progress watchdog, fixed owned destinations and clear error codes. A complete transfer still must pass the original checksum/signature or APK identity/certificate validation before activation/installation. A foreground-recovery download explicitly asks the player to keep the launcher open; its play button cannot silently destroy that request. Completed owned recovery files can be verified after restart. Superseded pending data requests are cleared.

APK recovery uses the existing validated installer, with additional narrowly scoped internal FileProvider paths for its owned update folder. Package name, certificate, project name and captain save paths are unchanged. The new build must be installed over the old app, preserving existing guest progress. Updater scripts are intentionally excluded from game-data packs, so this repair requires one bootstrap APK. Later compatible game changes again use signed data updates.

Regression coverage includes simulated native failures for both controllers, no duplicate recovery jobs, explicit retryable errors, preserved game access, blocked accidental scene transitions during foreground transfer, a real local HTTP 503 → retry → complete byte-for-byte file transfer, destination/URL rejection and proof that a completed direct download cannot bypass signed content verification. Existing updater, signed-pack and gameplay suites remain mandatory. Physical Android acceptance remains a device check.
